必须重启 app 才恢复。**

## 修复

### 热安装后面板 405：RPC 行的 provider 一次性解析

**症状**：KCoder / QiLin 桌面端在运行中经插件管理安装（或更新）本插件，侧边栏
面板能打开，但正文一直是红色
`加载失败: transport failure for /dsh-kylin-vibe/snapshot: HTTP 405`；
重启 app 后同一面板立即正常。工具面（`graphrag_*`）不受影响。

**根因**：`dsh-kylin-vibe/rpc` 行在 `apply()` 里**一次性** `service.resolve()`
取 provider，取不到就 `return`，且此后再无重试。热安装时 bundle 的四个行
（seam / provider / rpc / tool）是同一批新 entry 启动的，apply 先后顺序不保证：
provider 行还没注册时 rpc 行先 apply —> 路由永久缺席。POST 落到宿主的 SPA
静态 fallback（非 GET/HEAD 一律 405），于是面板拿到 405 而不是 JSON 信封。
冷启动时插入顺序恰好稳定，所以重启即好——这正是「必须重启 app」的来源。
（工具面不受影响是因为工具行在每次调用时才 `resolve()`，天然惰性。）

**修复**：`src/rpc.ts` 的 apply 改为**无条件注册路由、provider 每次请求惰性解析**
（`service.resolve(pin)` 放进请求闭包）。provider 暂缺时 `handleKbRpc` 的
`try/catch` 把它转成 `{ok:false, code:'NO_PROVIDER'}` 结果信封，面板 5s 轮询
在 provider 行就绪后自动恢复，无需重启宿主。

**回归测试**：新增 `tests/rpc.test.ts`（4 项）——① provider 尚未注册时 apply
仍注册 `/dsh-kylin-vibe` 前缀路由（旧实现在此失败）；② provider 暂缺返回
NO_PROVIDER 结果信封（而非传输层失败）；③ provider 已注册时 snapshot 行为不变；
④ 非 POST 仍 405（鉴权/围栏契约不变）。

## 变更

- **安装/升级语义澄清**：KCoder / QiLin 桌面端经插件管理安装/更新后，宿主行
  与客户端 bundle 由 profile HMR 就地重载，**不需要重启 app**；命令行
  `dsh plugin add` / `qilin plugin add` 安装到**另一个**进程时（例如正在运行的
  `dsh web`），仍需重启该进程——跨进程没有热装通道。README 安装段落已按此改写。
- 无接口契约变更：端点、请求/响应信封、鉴权围栏均不变。

## 删除

无。

## 兼容性与升级说明

- 面板 RPC 契约不变（`/dsh-kylin-vibe/{snapshot,createKb,…}`、`{ok,value}` /
  `{ok,error}` 信封、Host/Origin + 浏览器鉴权围栏不变）。
- 升级方式：`dsh plugin --profile <p> add dsh-kylin-vibe` / `qilin plugin --profile <p> add dsh-kylin-vibe`
  （桌面端安装后即时生效；CLI 安装的宿主进程需重启）。
- 若宿主仍在运行旧版本，面板照旧需要重启——本修复随 0.1.5 代码生效。

## 验证

- **真机（运行中的 KCoder 桌面宿主，未重启 app）**：安装态实测
  `POST /dsh-kylin-vibe/snapshot` 为 **405**（路由缺失，复现用户截图）；把修复后的
  `lib/rpc.js` 写入运行中 profile 的已安装包并触发一次 profile reconcile，
  同一请求变为 **401 `unauthorized`**——证明路由已注册、handler 已执行、只差
  浏览器鉴权（浏览器内面板随后正常）。恢复 profile patch 文件后路由保持，
  全程未重启 app。
- **离线**：`npm run check` 全绿——typecheck（含 client）+ **153/153** 测试

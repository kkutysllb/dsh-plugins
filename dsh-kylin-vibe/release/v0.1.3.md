v0.1.2 交付后用户质询：**建库表单里选了模型，agent 执行却报「插件配置文件没有模型」，难道还要手改配置文件？** 诊断属实——表单选的是会话模型（agent 对话用），图谱抽取模型只读插件配置且默认未配置、直接拒绝。本版本把这条链路打通：**表单选定的模型经 Agent 代建自动成为抽取模型，不再需要手改任何配置文件。**

## 新增
无。

## 变更
- **抽取模型解析序**：插件配置 `model.{provider, model}`（两项都非空，显式指定，优先级最高）> **会话路由跟随**（新增）> 报可操作指引。跟随路由在索引启动时定格一次（长索引期间切换会话模型不影响本次抽取一致性）；跟随路由不缓存、解析失败不缓存 null（顺带修复 llm 服务晚于插件就绪时永不恢复的旧问题）；
- 视觉抽取（图片多模态）仍只在显式配置 model 时启用：跟随会话路由可能选中无视觉能力的模型，明确降级为 vision-unavailable 优于文件级报错；
- 面板建库表单「会话模型」更名为「会话模型（Agent 对话用）」，并加行内说明：图谱抽取模型不在此选择——插件配置了 model 就用它，否则自动跟随这里选定的会话模型；
- cordis.patch.yml 的 model 注释改为与实现一致的准确描述。

## 修复
- **建库表单选定的模型对抽取不生效**（用户质询）：表单仅做会话级 durable 选择、抽取路由只读插件配置（默认未配置 → 抽取直接拒绝）→ provider 监听宿主 `session/event` 的 `request/header` 事件按会话记录模型路由（dsh-kylin-memory 真机验证过的宿主形态）；`graphrag_index` 现携带调用会话 id，抽取自动使用该会话当前模型；面板直接触发索引时回落全局最近一次会话路由；
- **NO_PROVIDER 错误信息改为可操作指引**：写明两条路径（宿主会话发一条消息 / 插件配置两项必填），agent 拿到即可照办指导用户，不再只说「没有模型」。

## 兼容性与升级说明
- 插件接口无破坏性变更：`index/indexBackground` 新增可选 sessionId 参数（不传行为为回落全局路由），`graphrag_*` 五工具契约不变；
- 已显式配置 `model.{provider, model}` 的部署不受影响（显式配置始终优先）；
- 升级：`dsh plugin --profile <p> add dsh-kylin-vibe`（或 GitHub / dsh-plugins 镜像任一渠道）后重启宿主。

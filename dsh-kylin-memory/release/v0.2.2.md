# v0.2.2

## 版本信息

- 发布日期：2026-10-06
- 基线：v0.2.1
- 主题：修复插件详情页设置卡"该插件当前未加载,暂时无法配置"——bundle 配置卡自取设置表单（引擎页面从不给 bundle 卡传 form）

## 背景

KCoder（DSH 0.2.1-alpha.1）上安装后详情页提示"该插件当前未加载,暂时无法配置。"，组件行却显示运行中。逐层定位（引擎源码 + 用户引擎的编译产物核验）：

1. 该横幅文案出自**本插件的 client 卡片**：`form === undefined` 时的分支（`src/client/index.tsx`）。
2. Plugins 页面构建共享表单的门是：宿主 settings describe 里存在 `ns === 卡片键` 的命名空间（`formFor(id)`）。
3. **引擎的页面只为 `plugins.item`（官方插件卡）与 `plugins.row.config`（行卡）传 form；`plugins.bundle.config`（bundle 配置卡）的渲染调用只传 `{ view: "page" }`，从不传 `form`**——已对照 QiLin 3.0.11 源码与 KCoder 运行时编译产物（`formFor` 仅有 row/item 两个调用点）双重确认。因此 bundle 配置卡自 v0.1.3 起在任何此类引擎上都不可能收到页面表单，与插件版本无关，v0.2.1 安装只是让该缺陷首次被看见。
4. 宿主半边没有问题：DSH 0.2.x 的 settings 服务直接从活动插件 fiber 的 `Config` 导出派生表单（`SettingsForms.describe`），实测 `volatileForm(Config)` 能生成含全部 5 个 volatile 字段的表单，命名空间即 profile 条目 id `dsh-kylin-memory`。

## 修复

- **设置卡自取表单**（`src/client/index.tsx`）：client 入口注入 QiLin 现役的 `configForms` 服务（ui-plugin-manager 自身同款依赖），对命名空间 `dsh-kylin-memory` 调 `configForms.get()` 拿到活动句柄，经槽位注册的 `inject` 面注入卡片并订阅快照保持响应式。页面若显式传了 `form`（未来的引擎行为）则优先采用。状态语义不变：`ready` 渲染表单、`loading` 显示加载中、`unavailable`（如非环回页面的进程内持久化）才显示"未加载"横幅。
- **宿主半边双代兼容**（`src/index.ts`）：对暴露 `settings.installSection` 的引擎（QiLin 3.0.x，其 settings 服务只服务显式注册的命名空间）feature-detect 注册命名空间 `dsh-kylin-memory`，并把解析后的 schema 字段采纳进插件配置使 `readLive()` 消费者即时看到改动；DSH 0.2.x 无此接口，动态注入自动跳过（表单由 fiber Config 派生）。失败语义 fail-open：注册被跳过只告警，不影响记忆功能。
- **设置卡补上第 5 个字段**：`archiveThresholdTokens`（v0.2.1 起配置面已有、设置卡此前实际未渲染），中英文标签与说明同批加入。

## 兼容性

- client 入口 `inject` 由 `["slots", "locale"]` 扩为 `["slots", "locale", "configForms"]`——注入的是 QiLin 现役 settings 服务（ui-plugin-manager 同款），并非 v0.2.0 退休的 DSH settings-form 原语；后者在产物内仍零残留（smoke 双向断言）。
- manifest（`dsh`/`qilin` 的 `client.inject` 依赖边）不变：`@deepseek-ai/dsh-client-ui-settings` 本就在列，它是 `configForms` 服务的提供方。
- 数据、schema、bundle patch 兼容：无迁移、无配置键变化。
- 已知边界：若某宿主既不给 bundle 卡传 form、settings 服务又缺少 `configForms`（极旧引擎），卡片保持"加载中"占位而非报错。

## 验证

- `tsc --noEmit` 零错误；186/186 单测（24 文件）全绿（新增 settings-namespace：installSection 注册、仅 schema 字段采纳、无接口引擎 no-op）；`npm run build` 产物更新；`npm run verify:package` OK。
- `npm run smoke` ALL PASS（client 注入面断言改为现役语义：`["slots", "locale", "configForms"]` + 卡片自取句柄；DSH settings-form 原语与退休服务调用仍零残留）；`npm run smoke:client` 通过并新增断言：槽位注册的 inject 面携带 configForms 句柄。
- 宿主半边兼容性实测（用户引擎同款运行时）：`volatileForm(Config)` 生成含 5 个 volatile 字段的表单，`projectForm` 正确投影存量覆盖值。
- 未重跑双通道真实宿主安装冒烟（本版未触及 manifest 与 host bundle 的加载面）。

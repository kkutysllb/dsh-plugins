# v0.2.1

## 版本信息

- 发布日期：2026-10-06
- 基线：v0.2.0
- 主题：表面压缩改阈值触发批量归档——修复逐轮滚动归档打穿前缀缓存导致的净成本上升（0201 缺陷 E1）

## 背景

真实用量测量：v0.2.0 及之前版本的上下文接管使缓存命中率直降 2-3 个百分点，token 消耗没有下降、净成本反而上升。根因：`freshTurnCount=5` 的滚动归档在窗口填满后**每轮**改写模型可见表面头部，provider 前缀缓存（按最长公共前缀匹配）从标记之后整体失配——新鲜窗口 + 召回快照按 1× 全价重付，而被省掉的旧历史原本只按 ~0.1× 命中价计费。盈亏平衡点约在"会话历史 ≈ 10× 保留窗口"，多数会话活不过这条线。完整分析见 [docs/01-tech/0106-表面压缩与前缀缓存经济学.md](../docs/01-tech/0106-表面压缩与前缀缓存经济学.md)。

## 变更

- **滚动归档 → 阈值触发批量归档**（`src/format/dsh-compaction.ts`）：
  - `selectDshRollingCompactionRange` 更名 `selectDshBatchArchiveRange`，触发条件改为双门：实测表面 token 超过 `archiveThresholdTokens` **且** 真实用户轮数超过保留数；其余范围计算（保护 system 头、折叠旧标记）不变；
  - 新增 `sumDshSurfaceTokens`：按宿主 `tokenMeter` 启发式价汇总表面；meter 不可用返回 null（不静默读作 0）；
  - 两次归档之间表面严格 append-only，前缀缓存持续命中；每次归档的全价重付被摊销到多个轮次。
- **归档标记逐字节恒定**：id 去掉每次变化的区间后缀（`kylin-memory-archive:{session}`），文本本就是常量；若宿主把事件 id 序列化进 prompt（未证实），此修复恰好覆盖，否则无害。V4 行准入对 `user/message` 的 `data.id` 无唯一性约束，已核实。
- **压缩门控 step===1**（`src/index.ts` compactBeforeStep）：与自动召回同门，轮中改写头部在结构上不可能（同时消除"step 2+ 仍携带 claimed 消息"契约下的轮中二次压缩隐患）；不传 `step` 的宿主保持旧的无门控行为。meter 不可用时每 agent 告警一次并跳过归档（fail-open）。
- **保留项**：轮末轨迹投影（`dsh-turn-projection.ts`）经济性为正（省掉 0.9× × 轨迹体积 × 后续所有请求），未改动。

## 新增

- 配置项 `archiveThresholdTokens`（默认 80000，启发式 token 口径）：批量归档的表面 token 阈值。三个入口：bundle patch（`cordis.patch.yml`）、宿主设置卡（第 5 个 volatile 字段，热调）、环境变量 `KYLIN_MEMORY_ARCHIVE_THRESHOLD_TOKENS`。调大 = 更少缓存失效，调小 = 更小表面；阈值低于保留窗口常态体积时退化为逐轮滚动（等价旧行为）。
- `freshTurnCount` 语义收窄为"批量归档触发时保留的最近轮数"；两次归档之间表面可超过 N 轮继续增长（刻意为缓存保留的性质，表面规模改由 token 阈值约束）。
- 压缩日志 enriched：记录归档时的表面 token 总量与归档后余量。

## 兼容性

- 配置向后兼容：不设 `archiveThresholdTokens` 时用默认值；不改 schema 迁移（仍 m1–m21）、不改既有配置键语义（`freshTurnCount` 的有效行为随之放宽而非收紧）。
- **行为变化**：会话前段（未达阈值）的表面比 v0.2.0 更大——这是用 0.1× 命中价换取的，净成本下降；若需 v0.2.0 的"硬上限 5 轮"行为，把 `archiveThresholdTokens` 调到低于 5 轮问答的体积即可（此时等价旧实现）。
- 双通道（DSH/QiLin）零分支：改动全部位于共用 format 层与适配器，manifest 无变化。

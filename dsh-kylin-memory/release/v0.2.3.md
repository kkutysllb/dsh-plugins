# v0.2.3

## 版本信息

- 发布日期：2026-10-06
- 基线：v0.2.2
- 主题：插件详情页设置卡按宿主设计语言重做——布局、质感与宿主自带设置页对齐（修复"标签/输入框/说明挤在一行"的无样式渲染）

## 背景

v0.2.0 按 QiLin 契约重写设置卡时，卡片只剩宿主原语 `Input` / `Button` 可用（QiLin 3.0.11 的 `@qilin/client-ui-primitives` 已退休 `SettingsForm` / `SettingsValueField` / `settingsNumberField`，DSH 0.2.x 的同名包才有），而原语自带的样式只有"控件壳"：`Input` 是 `display:inline-flex` 的自适应宽度控件、`Button` 是行内按钮，标签与 `<small>` 说明都是行内元素。缺少字段容器样式的结果就是截图里的样子——`保留最近轮数已覆盖 [50] 批量归档触发时… 恢复默认` 全挤成一行，输入框宽度随内容、说明文字跑到输入框右侧、恢复默认按钮像第三个标签。

也就是说：这一版不是"审美问题"，是**契约降级后丢掉了宿主设置表单的布局与令牌**，卡片在宿主页面里没有落回任何设计语言。

## 变更

- **设置卡自带样式表（`src/client/index.tsx` 的 `CARD_CSS` + `installStyles()`）**：逐条复用宿主自带设置表单的 CSS（`@deepseek-ai/dsh-client-ui-primitives` 的 `settings-form/fields.module.css` 与 `SettingsForm.module.css`）——同度量（字段 `padding:12px 0` + `gap:6px`、标签 13px/500、说明 12px、行间分隔 `0.5px`）、同令牌（`--dsw-alias-label-primary|secondary|tertiary`、`--dsw-alias-border-l2|l4`、`--dsw-alias-bg-layer-3`、`--dsw-alias-bg-module-platform`、`--dsw-radius-md|sm`、`--dsw-focus-ring-width`），全部挂在 `km-` 前缀下，每个令牌带字面量兜底。样式表按 `id="dsh-kylin-memory-settings-styles"` 每文档注入一次（幂等，`ctx.effect` 管理生命周期），不依赖任何宿主 UI 原语。
- **字段结构对齐宿主设置表单**：标签行（标签 + 右侧 `已覆盖` 药丸 + `恢复默认` 文本按钮）→ 整行输入框 → 下方说明（说明与错误态同一位置切换，`aria-describedby` 指向它）；字段之间细分割线；底部一行是唯一的保存按钮，失败文案出现在它左侧。
- **表单列宽 760px**：与宿主设置页内容列（`ui-settings-plugins` 的 `max-width:760px`）一致。插件详情页是通栏的，若让数值输入框铺满 1240px 会明显比宿主任何一处设置都难读。
- **文案不变**：五个字段的中英文标签、说明、`已覆盖` / `恢复默认` / `保存` / 只读与未加载提示沿用 v0.2.2 的词典。

## 修复

- 设置卡在宿主页面里"没有样式"：标签、输入框、说明、恢复默认按钮挤在一行，输入框宽度随内容伸缩（用户可见的丑）。
- 被覆盖标记从行内文字 `<span data-overridden>` 改为宿主同款药丸（`km-tag`，对应原语 `Tag tone="neutral"`），恢复默认从原语 `Button variant="ghost"` 改为宿主设置表单同款文本按钮。
- 保存按钮从原语 `Button variant="primary"`（品牌蓝）改为宿主设置表单同款 `--dsw-alias-label-primary` 实底按钮，与"设置 → 终端 / 子代理"等页面上的保存完全一致。

## 兼容性

- **client bundle 的模块表面收窄到 react**：不再 `require("@deepseek-ai/dsh-client-ui-primitives")`，只 `require("react")` + `require("react/jsx-runtime")`。这一步同时消除了两个引擎原语不同源带来的外观分歧（QiLin 的按钮是胶囊形 `border-radius:18px`，DSH 的 `--dsw-radius-md`），卡片外观从此是插件自己的属性。
- client 入口 `inject`（`slots` / `locale` / `configForms`）、槽位注册键、`form.state` / `form.mutate` 写入语义、覆盖判定（`state.user` 存在该键）与保存栅栏（revision）**全部未变**；宿主半边、数据、schema、bundle patch 零改动（`lib/index.js` 无差异）。
- 令牌兜底：宿主若未发布 alias 层，卡片回落到字面量配色（仍是完整可用的表单），不出现透明背景上的不可见文字。

## 验证

- `tsc --noEmit` 零错误（`tsconfig.json` 的 `lib` 增加 `DOM`：卡片这一版直接渲染原生 `input` / `button`；`include` 增加 `test/**/*.tsx`）。
- 194/194 单测（25 文件）全绿，新增 `test/client-card.test.tsx`（8 例）：字段顺序与标签/取值/`aria-describedby` 接线、`已覆盖` 与 `恢复默认` 只出现在用户层携带的字段上、唯一保存按钮且未编辑时禁用、只读部署的提示与全控件禁用、`unavailable` / `loading` 占位、`summary` 座位留空；样式表注入一次且 disposer 移除、无 `document` 时 no-op。
- `npm run build` 产物更新；`npm run smoke` ALL PASS（client 断言改为新契约：只向模块表要 react、产物自带 `km-` 样式表与 `--dsw-*` 令牌、DSH settings-form 原语零残留）；`npm run smoke:client` 通过并新增断言：`apply` 把样式表注入 `document` 且第二次 `apply` 不重复注入。
- 视觉核验：以宿主真实主题令牌（`@deepseek-ai/dsh-client-ui-theme` 的 base + design-platform CSS，浅色/深色两套）在离线页面里渲染卡片，与逐字复用宿主 `settings-form` CSS 的基准列并排比对——字段几何、标签字重、药丸、恢复默认、说明配色、保存按钮一致；并放进 1240px 宽的详情页上下文确认 760px 列宽的留白成立。
- 未重跑双通道真实宿主安装冒烟（本版不触及 manifest、host bundle 与注册契约）。

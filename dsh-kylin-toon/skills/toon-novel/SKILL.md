# 小说工作台：从零到一章

文件是权威，工具只做投影。先建结构，再写正文；每一章只装该章的上下文，绝不把整本书塞给模型。

## 0. 先判意图

新需求先调 `toon_intent({ text })`。只有 `medium=novel` 才进这条线；`drama/game/video/reference` 走各自工作台。

## 1. 立项（灵感与前提）

只问五个问题，问完就写：

1. 题材与核心卖点（读者为什么点进来）；
2. 平台与篇幅（起点/番茄/晋江；长篇/短篇；预计章数与每章字数）；
3. 目标读者；
4. 一句话故事（谁 + 想要什么 + 被什么挡住 + 代价）；
5. 基调（爽/虐/悬疑/治愈）与主角第一印象。

落 `灵感.md`；没有结构时先 `toon_novel_init({ title, genre, platform, length, logline, protagonist })`，它只补缺失文件。

## 2. 故事架构

填 `故事架构.md` 的骨架，不确定就写「待定」，但至少要有：

- 主线冲突、主角目标、对手/阻力、失败代价；
- 起点、中点转折、高潮、结局；
- 主题一句话；
- 3 条支线与 3 个伏笔（可后补）。

检验：把结局遮住，问「主角为什么不能掉头」；答不上来就是目标或代价没立住。

## 3. 世界观（设定.md，六类）

| 类目 | 写什么 | 检验 |
| --- | --- | --- |
| 世界规则 | 什么能做、什么不能做、违反的后果 | 能不能直接制造一场冲突 |
| 地理 | 地图、气候、交通、边界 | 赶路要多久，为什么不能直达 |
| 势力 | 组织、阵营、利益、内部矛盾 | 每个势力想要什么、怕什么 |
| 能力体系 | 等级、获得方式、代价、上限 | 升级要付什么，强者的弱点 |
| 时代与文化 | 技术、货币、礼俗、语言 | 日常细节能不能被角色用上 |
| 禁忌 | 底线、忌讳、触犯后的追责 | 主角触碰时谁来找麻烦 |

写法：每条「事实 + 代价 + 可冲突点」，一条只讲一件事；不写百科式罗列。正文要引用的条目标清楚，后续章节只取相关条目。

## 4. 人物（人物.md）

每张卡至少：

- 身份、欲望、目标、创伤、弧光、关系、口吻、首次出场；
- 主角与对手各一张，且欲望互相冲突；
- 配角只写「在这条线里起什么作用」，不写完整传记。

检验：把人物名遮住，只看台词能不能认出是谁。

## 5. 大纲（大纲.md）

- 分卷：每卷一个阶段性目标与卷末反转；
- 每章三行：目标、冲突、钩子；
- 前三章按「黄金三章」检查：第一章给钩子，第二章给升级，第三章给不可逆选择；
- 章数与正文进度对得上，不提前写远期细节。

## 6. 正文（正文.md）

每章只装五样东西：

1. 本章目标/冲突/钩子（大纲）；
2. 出场人物卡摘要；
3. 相关世界观条目（不相关的不要带）；
4. 上一章定稿末段；
5. 追踪里的连续性事实。

写完更新 `追踪.md`：未回收伏笔、人物状态、时间线。不要改大纲去迁就正文，除非明确调整剧情。

## 6.0 多书项目

一个工作区可以有多本书：每本在 `小说/<项目名>/` 下独立存放七份文件，指针在 `.kylin-toon/novel-active`。

- `toon_novel_init({ project: '小说/长夜行', title, ... })`：新建并激活一本；
- `toon_novel_project({ action: 'list' })` / `{ action: 'switch', project: '小说/长夜行' }`：查看与切换；
- 其他小说工具不需要改参数，自动跟随激活项目。

## 6.1 导入现成小说

已有稿子（.txt/.md）先用 `toon_novel_import({ path })`：识别「第N章 / Chapter N」切章，写成 `正文.md`，同时生成 `大纲.md` 章目；缺 `灵感.md` 时按导入信息补一份。已有正文默认不覆盖，`force: true` 才覆盖并备份为 `正文-导入前.md`。

导入只做结构，不替作者补人物、世界观与简介；导入后从 `toon_novel_status` 看缺口。

## 6.2 结构化编辑

- `toon_novel_world({ action, category, text?, index? })`：按类目增/改/删世界观条目；`category` 用 rule/geography/power/system/era/taboo；
- `toon_novel_character({ action, name, fields })`：按姓名新增或合并人物字段，`remove` 删除；
- 写入仍是 `设定.md` / `人物.md`，正文与大纲不会被顺带改动。

## 6.3 写作任务与定稿门

- `toon_novel_task({ number })`：生成 `章节/第N章/写作任务.md`，含字数目标、人物口吻、连续性、本章上下文与交付要求；写作 Agent 按它写草稿，不再自己拼上下文。
- `toon_novel_finalize({ number })`：定稿门——必须有审稿单且无阻断，才把 `草稿.md` 复制成 `定稿.md`；已有定稿默认不覆盖，确需覆盖传 `force`。
- 顺序固定：写作任务 → 草稿 → 审稿 → 定稿；不要手改状态。

## 6.4 自动审稿（规则）

写完草稿先跑 `toon_novel_review({ number })`，它按可解释规则生成 `审稿.md`：

- 阻断：草稿为空、蓝图目标为空；
- 提醒：字数偏离目标、目标未落地、钩子不在章末、出场人物没出现、设定类目为空、重复段落；
- 提示：冲突/连续性没写、引用设定不匹配、段落过长、对白比例异常、套话密度高。

审稿单分「阻断 / 提醒 / 提示 / 人工复审」四段；人工写的审稿不会被覆盖，自动版写 `审稿-自动.md`。审稿不改正文。

## 6.5 章节工作台（蓝图 → 草稿 → 审稿 → 定稿）

每章落在 `章节/第0001章/`：

| 文件 | 作用 |
| --- | --- |
| 蓝图.md | 本章目标、冲突、钩子、出场人物、引用设定 |
| 草稿.md | 第一稿正文 |
| 审稿.md | 问题单与修改要求 |
| 定稿.md | 可发布正文，也是下一章的「上一章结尾」来源 |

- `toon_novel_chapter({ action: 'create' })`：从大纲建下一章蓝图，自动填入目标/冲突/钩子；
- `toon_novel_chapter({ action: 'context', number })`：装配本章有限上下文（蓝图 + 出场人物摘要 + 相关世界观 + 上一章结尾 + 连续性）；
- 写草稿前先看上下文；写完更新 `追踪.md`，再进入审稿。
- 审阅时可以在文稿预览里划词，把选中原文 + 修改要求发给 Agent；Agent 定位到文件后直接改并说明改动。

## 6.8 发布与改编

- `toon_novel_publish`：汇总书名/笔名/分类/标签/简介/字数到 `发布资料.md`；缺的字段留空并列出，不编造简介。
- `toon_novel_adapt`：把已写章节或大纲映射成集数，输出 `改编计划.md`（保留人物与世界观、章节→集数），交给短剧/漫剧/游戏/解说线；只给计划，不伪造剧本。
- 改编前至少要有大纲或一章正文；没有可改编内容时先补大纲。

## 7. 状态与交接

- `toon_novel_status`：看阶段完成度、下一阶段、缺口；
- 需要切界面：`toon_production({ action: 'focus_workspace', kind: 'story' })`；
- 参考片/短剧改编：先走参考片拆解，再按改编目标进对应工作台。

## 边界

- 不覆盖已有正文；初始化只补缺失文件；
- 不把全书塞进单次上下文；
- 不替作者定题材与平台，只给结构化选项；
- 世界观不为「显得宏大」而写，每条都要能落到冲突或代价。

- **日期**：2026-11-07

- **主题**：流水线（Job）成为唯一制作模型 + 模板契约严格门 + 创建页重做与模型选择 + 驳回闭环

## 2. 新增

### 2.1 制作流水线（Job）与六道闸门

- 新增 Job 数据模型：`jobs/` 独立存储、artifact 多 revision、Job 素材、gate 记录、workorder 队列（同一 Job 串行）。
- 六道闸门：G0 立项 / G1 规划 / G2 产物 / G3 规范 / G4 视觉 / G5 交付；G0/G1/G4/G5 为用户闸门，G2/G3 为机器闸门。
- G3 失败自动生成修复工单，最多 3 轮，超限 blocked（严格阻断，无 override）。
- 新增 `ppts_job` 工具桥：认领 / 完成 / 失败 / 登记 artifact / 读取 Job 与 nextAction。
- 新增流水线 HTTP 面：`jobs.*`、`workorders.*`、`gates.*`、`qc.run`、`jobs/artifact-upload`、`jobs/material-upload`。

### 2.2 单一工作区（流水线唯一模型）

- 侧边栏「演示文稿」从「新建任务 / 最近任务 / 流水线」三个并列 tab 收敛为**一个工作区**：
  - 任务列表：Jobs（进行中 / 已交付 / 待处理）+ 历史任务；
  - 顶部唯一「新建制作」主按钮；
  - Job 详情：阶段轨 / 闸门 / 工单 / QC / 产物 / 模板契约 / 素材 / 纠正版上传。
- 新建制作页重做为「左侧 Brief 主表单 + 右侧粘性摘要卡」两栏：主题 / 快速开始 / 交付形态 / 工作区 / 模板 / 模型 / 更多选项 / 素材；右侧汇总与「开始制作」。
- 新建制作现在直接创建 Job：完整 Brief → 素材上传 → 自动通过 G0（提交即确认 Brief）→ 自动派规划工单。
- G0 批准自动派「立项与页面规划」工单；G1 批准自动派「按大纲生成演示文稿」工单；G2 通过关闭生成工单。
- 历史任务支持行内删除（确认后删除任务索引与任务目录；工作区产物文件不自动删）。

### 2.3 模型选择

- 新建制作页新增模型下拉，读取引擎 `modelDirectories` catalog（Provider · Model），默认「跟随引擎默认」。
- 选择随 `jobs.create` 落库到 Job；派出工单时应用到承载工单的会话（会话 binding 未就绪时重试；失败只降级，不阻断派单）。
- Job 详情头部显示已选模型；旧宿主/DSH 无 `modelDirectories` 时选择器自动隐藏。

### 2.4 驳回闭环

- G1/G4/G5 的「驳回」改为内联原因编辑器：必填原因/修改要求 + 快捷原因（视觉 / 内容 / 模板 / 结构）。
- 提交后写 `gate.note`，并生成修改工单：
  - G4/G5 → builder + build；
  - G1 → planner + plan。
- 修改工单 prompt 带驳回原因、当前产物路径、Brief、模板提示与「不要整份重做、登记新 revision」要求；提交时显式派单，不依赖单一 effect。
- 新 revision 落盘会重置 G3/G4/G5；G2/G3 就绪时自动跑 QC（失败保留手动重试入口），通过后回到 G4。

### 2.5 模板契约与一致性严格门

- 新增 `ppts_contract`：模板排版契约物化/读取，归一化 levelRules（字体别名、字号、行距、颜色）。
- 新增 `skills/ppts-pptx/scripts/check_template_conformance.py`：按 shape 的 `sp:<role>` 标签逐 role 校验字体/字号，继承字号解析；FAIL/UNVERIFIED 退出非 0。
- `ppts_task action=done` 对用户模板任务强制跑结构 / 排版 / 模板一致性三道门，未通过返回 `qc-blocked` 且任务不完成；无 override。
- 模板契约严格阻断：契约 missing/ambiguous 时阻止完成，要求补充规范或裁决，不按默认排版继续。

## 3. 变更

- **破坏性 UI 变更**：不再有「新建任务 / 最近任务 / 流水线」三个平级入口；默认落工作区任务列表，新建走单一「新建制作」。
- **制作模型变更**：新制作统一走 Job；旧 `task` 只作为「历史任务」只读打开，不再新建。
- `ppts_task` 仅服务历史任务；新流水线任务统一使用 `ppts_job`。
- 内置模板与用户模板分流：
  - 用户 `.pptx` 模板：读取 `ppts_contract`，走模板一致性门；
  - 内置模板：使用内置视觉风格，没有用户 `.pptx` 契约，跳过 `ppts_contract` 与模板一致性门；
  - 详情页明确显示「内置模板」及原因，不再把「无契约」误显示为「未选择模板」。
- Job 详情在 G2/G3 就绪时自动跑 QC；手动「运行质检」仍保留用于重试。
- 内置模板/用户模板工单 prompt 分流；用户模板仍要求 `sp:<role>` 标签。
- 设置页导航图标适配 QiLin 3.1.9+ `span.navIcon` 容器，修复新引擎双图标。
- 面板继续限宽 960px 居中，控件 13px 度量不变。

## 4. 修复

- 流水线列表/详情/QC/工单/契约视图接线；Gate 标签中英文化。
- Job QC 通过后残留修复工单导致 nextAction 指向过期工单。
- 模板一致性门对错误字号误放行；新增按 role 的 conformance checker。
- 模板契约 `levelRules` 与 `check_typography --spec` 形状不一致。
- 契约提取找不到 python-pptx 解释器；改为按模块探测。
- 驳回后只有 gate rejected、没有修改工单/没有派单：新增 host 侧修改工单 + 客户端显式派单与旧宿主兜底。
- 内置模板被显示为「未选择模板」：区分 builtin 与用户模板契约空态。
- 新进度页事件子类名与 `sp-event` 前缀冲突，冒烟计数误判。
- 历史任务删除入口缺失；新增行内删除与确认。

## 5. 删除

- 移除「新建任务 / 最近任务 / 流水线」三个并列一级入口（旧视图仍保留给历史任务详情）。
- 移除新任务走 `ppts_task` 的主路径（历史任务兼容保留）。
- 内置模板不再要求 `ppts_contract`（本来就没有 .pptx 契约）。

## 6. 兼容性与升级说明

- **升级方式**：替换包体后**重启宿主**（host 侧 Job/reject/模板 prompt 变更需要重载；仅刷新页面只更新 client）。client 会随页面刷新/重载更新。
- **peer 范围不变**：仍为 `>=0.1.0-rc.5 <1.0.0`，peer 全部 optional。
- **数据兼容**：
  - 旧任务仍在 `super-ppts/tasks/`，以「历史任务」只读打开；
  - 新 Job 在 `super-ppts/jobs/`；
  - 旧任务**没有**一键升级为 Job 的按钮（后续版本补）；需要新流水线能力时请新建 Job。
- **API 兼容**：`ppts_task`、`ppts_check`、`ppts_render`、`ppts_templates` 保留；新增 `ppts_contract`、`ppts_job`。
- **模板行为变化**：用户模板任务完成前必须通过模板一致性门；内置模板跳过该门。若需要字体/字号硬约束，请使用用户上传的 `.pptx` 模板。
- **G4/G5 驳回语义**：驳回会回到 build 并自动派修改工单；不再只是把闸门标成 rejected 后停住。

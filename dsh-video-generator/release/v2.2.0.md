## 新增

- **协议族 `comfy-studio`**：把生成段接到本机 **dsh-short-video-studio**（画布工作室）——
  由 studio 经其能力注册表派发到本地 ComfyUI（`http://localhost:8188`），实现**零通道配置**本地生成。
  - 允许槽：`image.master` / `image.shot` / `video`（图文生成面）。
  - 该族能力位：`tier?: "fast" | "balanced" | "quality"`（白名单），video 另有 `maxDurationSec`。
  - **非该族槽声明 `comfy-studio` 即丢弃**（错位守卫，同 `music` 族既有纪律）。
- **本地通道 `kind: "studio-local"`**：固定 id `studio-local`、缺省名「本地画布工作室」，
  `baseUrl` 固定 `studio://local`、`apiKey` 为空串；写入校验豁免 https 与 apiKey 长度检查，
  读侧形状守卫不再因缺 baseUrl/apiKey 丢弃它。
- **适配器 `src/providers/comfy-studio.ts`**：惰性 `import("dsh-short-video-studio")`，
  守卫 `typeof _internals.runRender === "function"`。
  - `submit`：后台跑 studio 的 `runRender`，返回 `jobId = "studio:<uuid>"`（内存 Map 存 promise）。
  - image 段：能力 `image.text2image`，宽高由 spec.size 解析；video 段：本地参考图经
    `importManualImage` 进画布后走 `video.image2video`（首帧绑定），无参考图走 `video.text2video`。
  - `status`：未决 → running / 成功 → done / 失败 → failed(error)；`fetch`：以
    `file://<abs>` 交付（meta 带 mediaType / bytes / studioNodeId）。
  - `quote`：`costEstimate = 0`；`health`：探测 ComfyUI `/system_stats` 可达性。
  - `capabilities`：image=true，video=true，tts=false。
- **客户端**：设置页通道管理新增「**添加本地画布工作室**」一键创建本地通道；
  本地通道行隐藏凭证字段并显示「本地」徽标；用途槽绑定时可选本地通道 + **档位选择器**。
- **`saveUrl` 支持 `file://`**：本地产物按拷贝落盘（而非 HTTP fetch），与云端通道产物同构。
- **新增单测**：协议错位守卫、本地通道校验豁免、适配器三态（注入假 studio 模块）、`estimate=0`、
  `file://` 落盘（清单与结果见下方「验证」）。

## 变更

- 版本 2.1.4 → 2.2.0。
- **`ProtocolFamily` 增 `comfy-studio`**；新增 `ChannelKind = 'openai-compat' | 'studio-local'`，
  `ChannelConfig.kind` 由字面量 `'openai-compat'` 放宽为该联合类型（**字段本身仍必填**——
  旧数据缺 `kind` 时由读侧守卫归一为 `openai-compat`）；`ChannelInput.kind` 为**可选**入参。
- **vault / slots 守卫放宽面**（仅限本地通道与 `comfy-studio` 族，其他 kind / 族校验不变）：
  1. 通道写入校验：`studio-local` 豁免 https 要求与 apiKey 长度要求
     （`baseUrl`/`apiKey` 由实现填为 `studio://local` / 空串；通道 id 白名单照旧校验）；
  2. 通道读侧形状守卫：不再因 `baseUrl`/`apiKey` 为空丢弃 `studio-local` 通道
     （读到时归一为 `studio://local` / 空串）；缺 `kind` 字段一律按 `openai-compat` 处理；
  3. 槽位绑定的能力位白名单**新增 `tier`**（`image.master` / `image.shot` / `video` 三槽）；
     `video` 的 `maxDurationSec` 与其余能力位**沿用既有白名单，未改动**。
     `tier` 只在该绑定协议为 `comfy-studio` 时留存（取值须属白名单），其他协议上的同名键在守卫中删除，
     不留死字段；`tier` 不进能力位缺省值（未选档位即缺省）。
  4. `updateChannel` 对本地通道的凭证面**显式报错**（`bad-request`："本地画布工作室通道没有
     baseUrl / apiKey，无需配置凭证"），而不是让 `studio://` 去撞 https 校验给出误导性诊断。
- **成本链路**：`estimateFor` 对 `binding.protocol === "comfy-studio"` 求值为 **0**，
  不触发成本确认（本地无花费）。
- **管线接线**：`ProviderSlotOptions` 增 `studio?: { hostCtx, exec }`，machine 的
  `providers.forSlot` 透传；`vgen_generate` 的 `execute(args, exec)` 原样把 exec 传进 studio 桥。
- README 增补「本地画布工作室（零通道配置）」一节（含四条已知限制的如实声明）。

## 修复

- **`file://` 交付路径在 Windows 上算错**（本版新代码内自修，非既有缺陷）：形如
  `file:///C:/Users/x/a.png` 的标准 Windows file URL 经简单去前缀会得到 `/C:/…`，在 win32 上不是
  合法路径；`file://C:\Users\x\a.png`（本插件在 Windows 上 `'file://' + absPath` 拼出的形态）
  又需要原样保留。现统一到 `src/file-url.ts` 的 `localPathOf`：去前缀 → 解码 → Windows 标准形式
  去掉多余根斜杠；文件名含裸 `%`（如 `50%.png`）时解码失败回落原文，不再抛 `URIError`。
  生产方（comfy-studio 适配器）与消费方（`shot-clip.saveUrl` 落盘）共用同一规则。
- **三槽都绑本地时首个视频镜必失败**：图槽 `submit` 返回的 `file://<abs>` 被当作 url 落进
  `shot-urls`，video 段 i2v 又原样回灌成 `imageUrl`，旧实现直接 `readFileSync` 该字符串 → ENOENT。
  现经 `localPathOf` 归一后读盘（含 URL 编码路径）。
- **`vgen_review` 重拍在本地视频槽上双失效**：估价缺 `comfy-studio → 0` 分支（会被「未知价一律
  确认」多拦一次）；且未透传 studio 桥（真机必抛 `StudioUnavailableError`）。现与 `vgen_generate`
  同口径：估价 0 + 透传 `{ hostCtx, exec }`。
- 以上三条均有回归测试（`test/comfy-studio.test.ts` / `test/review.test.ts`）。

## 兼容性与升级说明

- **无需数据迁移**：旧 `vault.json` 中的通道**没有 `kind` 字段时按 `openai-compat` 处理**
  （与既有行为完全一致）；`studio-local` 是新增可选值，旧版本读到它只会照旧校验而丢弃该通道，
  不影响其余数据。**回滚**：不绑本地通道即可完全回到 v2.1.4 行为，vault 无需改写。
- **协议族旧值全部保留**：`openai-images` / `openai-tts` / `dashscope-video` / `kling-video` /
  `openai-video` / `generic-music` 语义与校验不变；`comfy-studio` 只对
  `image.master` / `image.shot` / `video` 三槽开放。
- **工具面不变**：仍是 10 个工具；`vgen_generate` / `vgen_channels` 的入参与错误信封形状未改
  （本地通道只是多一种槽位绑定目标）。
- **运行前置**：目标机需已装 dsh-short-video-studio 且 ComfyUI 在 `localhost:8188` 上运行；
  不满足时本地通道的健康探测与生成会**明确报错**，不会静默降级到其他通道。
- **兼容门不变**：`>=0.1.0-rc.5 <1.0.0 || >=3.0.0 <4.0.0`（7 条 peer 全部 optional）。
- **peer 兼容门注意事项（待真机确认）**：studio 的预发布版本（如 `0.2.1-alpha.2`）在
  `semver.satisfies` 不带 `includePrerelease` 时求值为 false——0.x 预发布宿主是否会被静默禁用以
  **安装实测**为准；QiLin 3.1.6 走右支（`>=3.0.0 <4.0.0`）应放行。

## 已知限制（本版如实记录，未修）

1. **依赖 studio 内部通道 `_internals`**：studio 未提供 cordis service，`_internals` 是其自述的
   内部通道；studio 升级可能变形状。适配器有存在性与形状守卫，**缺失时明确报错**（不静默降级）。
2. **成片归一化丢弃视频模型原生音轨**：归一化段仍 `-an`，H3 等 AV 模型自带的声音会被丢弃；
   配音（`tts`）与 BGM（`music.bgm`）不受影响。
3. **`quality` 档单镜视频可能超出 `vgen_generate` 的 600s 工具窗口**：建议 `fast` / `balanced`。
   各档实际耗时 **待真机确认**（下表留占位）。
4. **本地生成不在 `/api/pricing` 口径内**：成本记账为 0。
5. **本功能的目标环境是 NVIDIA（CUDA）+ Windows**：档位工作流、fp8 权重与模型文件名分隔符
   都按该环境配置。本插件只负责把「能力 + 档位」转给工作室，**不校验后端 dtype、也不代管模型供给**；
   非目标环境（如 Apple GPU / MPS）会在 ComfyUI 节点侧报 dtype 错，缺模型文件会报 `value_not_in_list`
   ——两者都是环境问题，照 ComfyUI 的原文提示处理（取证见下「目标运行环境」）。
6. **模型文件名分隔符随平台**：Windows 上用 `\`（工作室默认即如此），macOS / Linux 上用 `/`。
   本版**不**改写工作室配置文件。

### 目标运行环境：NVIDIA（CUDA）+ Windows

本地画布工作室的执行面（档位工作流、fp8 权重、模型文件名的分隔符）按 **N 卡 + Windows** 配置。
本版验收在 macOS 开发机上完成，下表是**该机与目标环境的差异取证**，既不是本插件缺陷，也不适用于目标机器：

| 现象（macOS 开发机） | 原因 | 目标环境（N 卡 + Windows） |
|---|---|---|
| FLUX fp8 在采样节点报 `Trying to convert Float8_e4m3fn to the MPS backend …` | Apple GPU 的 MPS 后端不支持 fp8 dtype | CUDA 支持 fp8，按工作室默认档位即可 |
| 换成 bf16 权重后仍在节点侧报错 | 开发机模型供给不全（`lora` 目录为空、缺 H3 的 `vae`） | 依工作室默认值装齐模型后按档位解析 |
| 配置里模型名写作 `Flux-2-klein\…` / `MiniMax_H3\…`，ComfyUI 判 `value_not_in_list` | 反斜杠是 Windows 约定；macOS 上该名字列表用 `/` | Windows 上反斜杠即正确形态 |

⇒ 「单镜视频实测耗时」本版**仍无法给出**：需在目标机（N 卡 + Windows）跑一次才能回填（下表保留占位）。
本插件侧只保证：把「能力 + 档位」转给工作室、零成本记账、`file://` 交付、错误原文回传、**不静默降级**——
这些均已实测通过（见上表）。
